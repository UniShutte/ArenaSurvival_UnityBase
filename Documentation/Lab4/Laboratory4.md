# Лабораторная работа №4

## Cinemachine, HUD, Animator, состояния раунда и безопасное ожидание

- **Дисциплина:** «Основы работы с Unity».
- **Проект:** Arena Survival.
- **Формат:** индивидуально, 20 баллов.
- **Предварительное условие:** рабочий результат ЛР3.
- **Редакция:** 3 октября 2026 года.

## 1. Результат работы

После выполнения работы игрок проходит прежний маршрут и поражает четыре цели,
но камера управляется через Cinemachine, а состояние игры видно в интерфейсе.
Последнее попадание завершает раунд и освобождает курсор. Кнопка Restart запускает
трёхсекундное ожидание, затем заново загружает сцену. Выход из Play Mode или
отключение контроллера раунда отменяет ещё не завершённое ожидание.

Вы создадите:

- сценовую Main Camera с Cinemachine Brain;
- виртуальную камеру, следующую за созданным во время игры персонажем;
- Canvas с прицелом, четырьмя шкалами здоровья и счётчиком целей;
- Animator с состояниями Idle, Hit и Completed;
- игровую машину состояний Playing, Completed и Restarting;
- временное уведомление через coroutine;
- отменяемую асинхронную операцию через `Task.Delay` и `CancellationToken`.

Готовые компоненты находятся рядом с методичкой в каталоге `Scripts`.
Сначала изучите их назначение, затем подключите и настройте в редакторе.
Переписывать систему стрельбы, пул и `Health` не требуется.

**Важно:** исходный репозиторий намеренно содержит завершённую ЛР3, а не готовую
ЛР4. Каталог `Documentation/Lab4/Scripts` находится вне `Assets`, поэтому Unity
не компилирует эти файлы до их переноса в учебном задании.

## 4. Архитектура

```text
PlayerSpawner -> Instantiate(Player)
                       |
                       +-- PlayerMovement / PlayerLook / Weapon (из ЛР3)
                       +-- CameraFollowTarget -> CM_PlayerCamera.Follow
                       +-- CameraTarget
                             +-- FirePoint

Main Camera + CinemachineBrain <- CM_PlayerCamera
                                 Body: Hard Lock To Target
                                 Aim: Same As Follow Target

Projectile -> Health -> HealthChanged -> TargetHealthBar (значение HP)
                    |                -> ArenaSession.TargetHit -> ArenaHud
                    +-> Died         -> ArenaSession.Changed   -> ArenaHud

ArenaHud -> Animator: Hit / Completed
         -> Coroutine: кратковременное уведомление
         -> Button -> ArenaSession.Restart -> Task.Delay -> загрузка сцены
```

`Health` не знает о Canvas. `Projectile` не знает об Animator. `ArenaSession`
хранит состояние раунда, а представления отображают данные. События позволяют
соединить компоненты без поиска UI в каждом выстреле.

В данной работе один Player и одна активная виртуальная камера. Поэтому
`CameraFollowTarget` один раз находит её в `Start`. Для нескольких игроков или
камер потребовалась бы явная привязка конкретной камеры через спавнер.

## 6. Камера Cinemachine

### 6.1. Подготовка player prefab

1. Остановите Play Mode.
2. Откройте `PF_FirstPersonPlayer` в Prefab Mode.
3. Переименуйте дочерний `PlayerCamera` в `CameraTarget`.
4. Сохраните его локальную позицию `(0, 0.7, 0)` и масштаб `(1, 1, 1)`.
5. Удалите с него `AudioListener`, `Universal Additional Camera Data` и `Camera`.
   Сначала удаляйте зависимый Additional Camera Data, затем Camera.
   **Не удаляйте сам GameObject или его Transform.**
6. Назначьте этому объекту Unity tag `Untagged`. Unity tags объектов не имеют
   отношения к Git-тегам, отказ от Git-тегов не запрещает Unity tag `MainCamera`.
7. На корне Player у `PlayerLook` явно назначьте `Camera Transform = CameraTarget`.
   Автоматический поиск дочерней Camera теперь не сработает, потому что её больше нет.
8. Сохраните дочерний `FirePoint` под `CameraTarget`. Для прицельной стрельбы
   установите ему local position `(0, 0, 0.5)`, rotation `(0, 0, 0)`.
   В `Weapon.Fire Point` должна оставаться ссылка на этот Transform.
9. Добавьте на корень Player компонент `CameraFollowTarget` и назначьте
   `Camera Target = CameraTarget` из этого же prefab.
10. Сохраните prefab и выйдите из Prefab Mode.

Повороты остаются в `PlayerLook`: yaw вращает тело вокруг Y, pitch вращает
`CameraTarget` вокруг X. Cinemachine не должен вторично читать мышь или повторно
вращать тело. Не добавляйте Cinemachine POV, FreeLook или Input Provider.

### 6.2. Реальная и виртуальная камеры

1. В сцене создайте пустой `Cameras`, Transform сбросьте в identity.
2. Под ним создайте **Camera**, назовите `Main Camera`.
3. Назначьте Unity tag `MainCamera`. Оставьте Camera, AudioListener и компонент
   URP Additional Camera Data, если редактор добавил его автоматически.
4. Добавьте **Cinemachine Brain**. Установите Update Method = **Late Update**,
   Blend Update Method = **Late Update**, Default Blend = **Cut**.
5. Создайте **GameObject → Cinemachine → Virtual Camera** и назовите
   `CM_PlayerCamera`. Перенесите её под `Cameras`.
6. У виртуальной камеры выставьте Priority = 10, Lens FOV = 60,
   Near Clip Plane = 0.05, Far Clip Plane = 500.
7. Выберите Body = **Hard Lock To Target**, Damping = 0.
8. Выберите Aim = **Same As Follow Target**, Damping = 0.
9. Follow и Look At оставьте пустыми в Edit Mode. Follow назначается после
   создания Player, а Look At намеренно остаётся пустым.
10. Если меню автоматически создало дополнительную Main Camera, удалите именно
    дубликат. В Play Mode должны быть ровно **одна Camera и один AudioListener**.

Реальная Camera формирует изображение. Virtual Camera описывает положение,
ориентацию и объектив; Cinemachine Brain применяет её состояние к реальной камере.
`Late Update` выбран потому, что `PlayerLook` меняет ориентацию в `Update`.

### 6.3. Контрольная точка A

- В Play Mode появляется Player, у `CM_PlayerCamera.Follow` виден его CameraTarget.
- Камера следует при движении и прыжке, горизонт не наклоняется.
- Мышь не вращает камеру дважды; Escape освобождает курсор.
- Снаряд летит вдоль взгляда. При возврате после падения камера возвращается с Player.
- В Console нет сообщений о нескольких AudioListener или неназначенной камере.

Зафиксируйте этап: `Connect Cinemachine to spawned player`.

## 7. Контроллер раунда

1. Создайте пустой `Gameplay/ArenaSession` и добавьте `ArenaSession`.
2. Увеличьте массив Targets до **4**.
3. Перетащите в него четыре **сценовых** объекта с компонентом `Health`.
   Не используйте prefab из Project и не назначайте одну цель несколько раз.
4. Установите Restart Delay Seconds = **3**.
5. Не добавляйте `Health` на этот объект и не переносите туда `TargetDeathHandler`.

Ссылки на цели сохраняются и после их `SetActive(false)`: отключение не является
уничтожением. Поэтому контроллер может посчитать цели с `CurrentHealth == 0`.
Подписки устанавливаются в `OnEnable`, снимаются в `OnDisable`.

| Состояние | Как достигается | Что разрешено |
| --- | --- | --- |
| Playing | Начало сцены | Движение, обзор, стрельба |
| Completed | Все назначенные цели имеют 0 HP | Работа с кнопкой Restart |
| Restarting | Нажатие Restart в Completed | Ожидание; повторный запуск запрещён |

В Completed контроллер отключает у Player компоненты `PlayerLook`, `Weapon`
и `PlayerMovement`. `PlayerLook.OnDisable` освобождает курсор. Персонаж остаётся
на месте; гравитация его контроллера также приостанавливается до загрузки сцены.
Это завершение учебного раунда, а не универсальная реализация паузы.

Так курсор не захватывается снова при клике по кнопке. Одного
`Cursor.lockState = None` недостаточно: прежний `PlayerLook` захватил бы его
при следующем нажатии мыши. В новом экземпляре сцены компоненты снова включены.

## 8. Создание HUD

### 8.1. Canvas и EventSystem

1. Создайте **GameObject → UI → Canvas**, назовите `HUD`.
2. Render Mode = **Screen Space - Overlay**.
3. Canvas Scaler: UI Scale Mode = **Scale With Screen Size**,
   Reference Resolution = **1920 × 1080**, Screen Match Mode = Match Width Or Height,
   Match = **0.5**.
4. Оставьте `Graphic Raycaster` включённым.
5. Создайте EventSystem, если он не появился автоматически.
6. На единственном EventSystem используйте **Input System UI Input Module**,

7. Если Actions Asset и ссылки UI-действий пустые, нажмите **Assign Default Actions**
   у InputSystemUIInputModule. Point, Left Click, Move, Submit и Cancel должны

8. При первом создании текста TMP выполните **Import TMP Essentials**.

Для первоначальной проверки используйте латинские UI-надписи из примера.

### 8.2. Иерархия и расположение

```text
HUD (Canvas, CanvasScaler, GraphicRaycaster, ArenaHud)
├── Crosshair (TMP)
├── ProgressText (TMP)
├── TargetRows
│   ├── Target_50 (TargetHealthBar)
│   │   ├── Label (TMP)

│   └── Target_200
├── NotificationText (TMP)
```

Положение в таблице задаётся относительно anchor с указанным pivot:

| Объект | Anchor / pivot | Anchored Position | Size | Рекомендация |
| --- | --- | --- | --- | --- |
| Crosshair | Center / Center | 0, 0 | 32 × 32 | `+`, размер 26, center |
| ProgressText | Top Left / Top Left | 32, -28 | 440 × 44 | Размер 30 |
| TargetRows | Top Left / Top Left | 32, -90 | 400 × 280 | 4 строки по 64 px |

При выборе anchor удерживайте Alt, только если хотите также изменить позицию
и pivot. После этого проверьте числовые значения Rect Transform.

Не размещайте элементы только вручную «на глаз» без настройки anchors.
У текста, прицела и FeedbackVisual выключите **Raycast Target**. Декоративная
графика не должна перехватывать нажатия на кнопку.

### 8.3. Одна строка здоровья

1. Создайте `Target_50` как UI-объект с Rect Transform размером 400 × 56.
   Anchor и pivot = Top Left, Anchored Position = `(0, 0)` относительно TargetRows.
2. Подпись Label: `Target 50`, размер 20, левое выравнивание.
3. Создайте UI Slider без пользовательского изменения: снимите **Interactable**,
   Transition = None. Можно удалить Handle Slide Area, очистив Handle Rect.
4. Slider разместите под подписью: anchor/pivot Bottom Left, position `(0, 0)`,
   ширина 260, высота 16, направление Left To Right.
   У Background и Fill выключите Raycast Target.
5. ValueText разместите справа: anchor/pivot Top Right, position `(0, 0)`,
   ширина 120, текст `50 / 50`, размер 20.
6. Добавьте на корень строки `TargetHealthBar`.
7. Назначьте Target = сценовая цель с Maximum Health 50,
   Health Slider = Slider строки, Value Text = TMP-компонент ValueText.
8. Создайте ещё три строки, сдвинув их вниз на 64, 128 и 192 px.
   Назначьте **разные** цели с 100, 150 и 200 HP.

Значения min/max и текущее положение Slider устанавливаются из модели.
Код использует `SetValueWithoutNotify`, потому что это индикатор, а не ввод.
При отключении цели строка остаётся на Canvas и показывает `0 / Maximum`.
Не делайте строки дочерними объектами целей: тогда они исчезнут вместе с ними.

Для повторного использования можно сохранить строку как `PF_TargetHealthRow`.
Ссылки на **сценовые** цели назначайте экземплярам строки в сцене, а не prefab.
Не применяйте сценовые ссылки к prefab через Apply All.

## 9. Animator: визуальные состояния

В этой работе анимируется маленький UI-индикатор, а не исчезающая цель.
`TargetDeathHandler` из ЛР3 сразу отключает цель, поэтому её анимация смерти
не успела бы проиграться без отдельного изменения архитектуры.

### 9.1. Контроллер и клипы

1. Создайте `Assets/_Project/Animations/HUD/AC_ArenaFeedback.controller`.
2. Назначьте его Animator на `FeedbackVisual`. Culling Mode = Always Animate.
3. Откройте **Window → Animation → Animation**, выберите FeedbackVisual.
4. Создайте три клипа: `HUD_Idle.anim`, `HUD_Hit.anim`, `HUD_Completed.anim`.
5. Анимируйте **только** `RectTransform.localScale` этого индикатора и `Image.Color`.
   Не анимируйте весь Canvas, положение прицела, Slider или кнопку.

| Клип | Длительность и ключи | Loop Time |
| --- | --- | --- |
| HUD_Idle | 0 и 1 с: scale `(1,1,1)`, цвет белый, alpha 0.35 | On |
| HUD_Hit | 0 с: scale 1; 0.08 с: scale 1.8; 0.25 с: scale 1; цвет жёлтый, alpha 1 | Off |
| HUD_Completed | 0 и 1 с: scale `(1.3,1.3,1)`, цвет зелёный, alpha 1 | On |

Для записи ключа переместите playhead в нужное время и включите Record.
После записи выключите Record, иначе изменения Inspector могут попасть в клип.
Ключ scale 1 означает `(1,1,1)`; увеличивайте X/Y равномерно.

### 9.2. Состояния, параметры, переходы

Откройте Animator. Создайте состояния с именами **Idle**, **Hit**, **Completed**
и назначьте им соответствующие клипы. Idle сделайте Default State.

Создайте параметры с точным регистром:

- `Hit`: **Trigger**;
- `Completed`: **Bool**, значение по умолчанию false.

Настройте переходы:

| Переход | Conditions | Has Exit Time | Duration |
| --- | --- | --- | --- |
| Any State → Completed | Completed = true | Off | 0 |
| Any State → Hit | Hit; Completed = false | Off | 0 |
| Hit → Idle | Completed = false | On, Exit Time 1 | 0.05 |

Для Any State → Completed отключите **Can Transition To Self**, иначе
анимация будет повторно входить в то же состояние. Для Any State → Hit
включите Can Transition To Self, чтобы очередное попадание запускало импульс заново.
Переход в Completed разместите выше перехода в Hit. Обратный переход из
Completed не нужен: новая сцена создаёт новый Animator в Idle.

После последнего попадания `ArenaHud` устанавливает Completed = true и сбрасывает
Trigger Hit. Краткая анимация попадания не должна перекрывать финальный статус.

### 9.3. Контрольная точка B

- В начале видны четыре полные шкалы, `Targets: 0 / 4`, кнопки нет.
- Попадание уменьшает только шкалу соответствующей цели на 25 HP.
- Видны импульс Hit и сообщение `Hit!` примерно на 0.6 с.
- Быстрые попадания продлевают сообщение, а не создают независимые таймеры очистки.
- При смерти цели счётчик увеличивается ровно на 1.
- После последней цели: `Targets: 4 / 4`, зелёный индикатор, сообщение победы,
  свободный курсор, доступная кнопка Restart.

Зафиксируйте этап: `Add event-driven target HUD and feedback animator`.

## 10. Coroutine: временное уведомление

Откройте `ArenaHud.cs` и найдите `ShowHit`, `HitNotice`, `StopNotification`.

```text
TargetHit -> остановить прежнюю coroutine -> показать Hit!
          -> WaitForSecondsRealtime(0.6) -> очистить текст
```

Coroutine не создаёт отдельный поток. Она приостанавливает выполнение метода
между кадрами. `WaitForSecondsRealtime` выбран, чтобы длительность уведомления
не зависела от `Time.timeScale`.

Хранится только одна coroutine. Иначе старый таймер мог бы очистить текст нового
попадания раньше срока. При завершении раунда и в `OnDisable` ожидание явно
останавливается. Финальное сообщение поэтому не исчезает через 0.6 с.

**Эксперимент:** сделайте два попадания с интервалом менее 0.6 с. Затем нанесите
последний урон и подождите секунду. Объясните, почему сообщение победы сохранилось.

## 11. async/await: перезапуск и отмена

Откройте `ArenaSession.cs`, найдите `Restart` и `OnDisable`.

```text
Completed -> Restart() -> Restarting
          -> await Task.Delay(3 seconds, token)
          -> проверить token -> LoadSceneAsync(activeScene.path)

OnDisable -> Cancel -> OperationCanceledException -> выход без загрузки
```

`async void` используется только на границе события Unity Button, где требуется
метод без возвращаемого значения. Исключения внутри обработаны. В обычных
асинхронных методах предпочитайте возвращать `Task`, чтобы вызывающий код мог
ожидать завершения и обрабатывать ошибки.

`Task.Delay` не блокирует главный поток и не зависит от игрового timeScale.
Продолжение здесь возвращается в контекст Unity: метод вызывается кнопкой
в главном потоке, `Task.Run` и `ConfigureAwait(false)` не используются.
Не переносите обращения к GameObject и SceneManager в фоновый поток.

В данной реализации отменяется **задержка до загрузки**, а не уже начавшаяся
операция `SceneManager.LoadSceneAsync`. У API загрузки сцены здесь нет переданного
CancellationToken. Эта граница важна: обещать отмену уже начавшейся загрузки нельзя.

### Практическая проверка

1. Уничтожьте четыре цели.
2. Нажмите Restart: кнопка должна стать неактивной, текст измениться на Restarting.
3. Несколько быстрых кликов не должны запустить несколько загрузок.
4. Через три секунды сцена начинает загружаться; время самой загрузки дополнительно.
5. После загрузки снова видны четыре цели, полные шкалы и счётчик 0 / 4.
6. Завершите раунд ещё раз, нажмите Restart и в течение трёх секунд выключите
   **компонент ArenaSession** через Inspector. Не отключайте цель или весь Canvas.
7. Подождите более трёх секунд: сцена не должна перезагрузиться, ошибок быть не должно.
8. Включите ArenaSession обратно: состояние пересчитается, Restart снова доступен.
9. Повторите запуск ожидания и выйдите из Play Mode до его окончания.
   Не должно появиться позднего обращения к уничтоженной сцене.

Не используйте `Thread.Sleep`: он заморозит редактор/игру вместо ожидания.
Не вызывайте ResetHealth отдельно у отключённых целей для нового раунда:
перезапуск сцены восстанавливает также Player, HUD, Animator и пул.

Зафиксируйте этап: `Add cancellable round restart`.

## 13. Частые ошибки

| Симптом | Что проверить |
| --- | --- |
| `Cinemachine` / `TMP_Text` / `Slider` не найден | Новый asmdef и его четыре references; установленные пакеты |
| Не удаётся добавить компонент | Имя файла совпадает с классом; нет ошибок компиляции или дублей |
| Камера осталась в начале координат | CameraFollowTarget на корне созданного Player; Camera Target назначен; одна активная VCam |
| PlayerLook отключается с ошибкой | Camera Transform явно назначен после удаления Camera из prefab |
| Камера дёргается или мышь слишком чувствительная | Нет POV/Input Provider/FreeLook; Brain в Late Update; нет второго скрипта обзора |
| Несколько AudioListener | Удалён старый компонент из prefab; не создана лишняя Main Camera |
| Follow пустой до Play | Это ожидаемо: экземпляр Player ещё не создан |
| Slider исчез вместе с целью | UI ошибочно помещён под цель, а не под Canvas |
| Все шкалы меняются одинаково | У всех строк ошибочно назначена одна и та же Health |
| Счётчик завершается слишком рано | В Targets не четыре уникальные сценовые цели |
| Здоровье уменьшается, а цель не исчезает | TargetDeathHandler включён на корне; Collider и Health на том же объекте |
| Animator не реагирует | Controller назначен; Hit именно Trigger; Completed именно Bool; совпадает регистр |
| Победа быстро исчезает | Coroutine должна останавливаться перед финальным сообщением |
| Кнопка не нажимается | EventSystem, InputSystemUIInputModule и UI Actions; Graphic Raycaster; курсор свободен |
| При клике курсор захватывается снова | По завершении должен отключаться PlayerLook, а не только изменяться Cursor.lockState |
| Restart сообщает об ошибке сцены | Активная сцена сохранена и включена в Build Profiles Scene List |
| Ошибка после выхода из Play | CTS отменяется и освобождается в OnDisable; не удалён catch отмены |
| Кириллица отображается квадратами | Нужен TMP Font Asset с нужным набором символов |

Сначала исправляйте первую ошибку в Console. Не добавляйте поиск компонентов
каждый кадр или бесконечные null-проверки вместо назначения зависимостей.
